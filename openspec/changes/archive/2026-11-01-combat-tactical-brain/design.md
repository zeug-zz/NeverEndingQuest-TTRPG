# Design

## Context

See `proposal.md` for the opportunity and scope. The 4b enemy resolver already plans a complete deterministic attack ledger before writes, preserves whole-batch fallback for unsupported mechanics, owns attack math, and provides one narration-only call for supported batches. Its near-death and leader-down boundaries remain relevant. The existing encounter schema accepts `leader: boolean`, and the enemy status lifecycle is limited to `alive`, `dead`, `unconscious`, and `defeated`; XP and combat exit already consume `defeated`.

The reusable boundaries are the existing resolver, enemy batch orchestrator, narration and persistence stages, PC `/att` path, opt-in trace/report pipeline, and Capture_Arena G5R tooling. This change adds a constrained tactical choice layer and encounter-scoped cover; it does not replace those boundaries or add a new combat loop.

## Goals / Non-Goals

**Goals:**

- Allow one explicitly designated commander to choose among Python-created legal options while keeping all mechanics and state changes Python-owned.
- Preserve the deterministic rule tier as the default and the existing whole-batch fallback for unsupported mechanics and unavailable commander authority.
- Let a commander-led side use Python-issued per-creature flee and surrender choices when legal, recording the reason without adding an encounter status.
- Make cover explicit, encounter-scoped, and visible to both code-owned attack comparisons without writing character files.
- Add optional PC-phase standing-orders prefetch, compiled against current `/end` menus with at most one event-triggered re-plan per batch and separate background-request accounting.
- Measure commander behavior with separate G5T scenarios and unchanged G5 absolute targets while retaining G1/G3/G4/G5/G5R compatibility.

**Non-Goals:**

- No ally controller, absent-PC autopilot, grid or position reasoning, movement, spell or save resolution, new conditions beyond cover, legendary actions, or streaming.
- No new enemy mechanics beyond the existing deterministic resolver's supported action set; the commander cannot make an unsupported batch eligible.
- No `fled` encounter status, grid/position movement simulation, character-file cover persistence, XP-policy change, new validation provider request, or change to existing G5R scripted actions or identities. Fleeing through the existing combat exit lifecycle is in scope.
- No flag enablement in shipped defaults as a result of G5T PASS alone; rollout remains a separate decision.

## Decisions

### D1. Store tactic authority on the encounter combatant

Add optional `tactics` to enemy encounter combatants with values `rule` and `commander`; absence means `rule`. A commander plan is authorized only when exactly one living enemy has both `leader=true` and `tactics=commander`. This uses the existing encounter projection and leader marker, requires no name/role inference, and leaves old encounters valid. Other scheduled enemies are represented in that commander's menus; their absent or `rule` tier does not disable an explicitly designated commander.

**Simpler alternative considered:** Put one global tactic field on the encounter. Rejected because it cannot identify which creature may issue side-wide choices and encourages inferred leadership.

### D2. Build bounded menu options before asking the commander

Only after the existing resolver confirms the entire batch's mechanics and lifecycle are supported, Python constructs one menu per scheduled actor. Menus contain opaque batch-local string option IDs for supported authored attacks against already-legal targets, authored cover choices, and legal self-preservation choices. A living creature at or below bloodied may receive a per-creature `flee` option; a living creature above bloodied may receive a conditional `flee` option only alongside a Python-issued commander withdrawal-order option. The plan must select that withdrawal order for the conditional choice to be legal. A living creature at or below the existing <=25% near-death boundary may receive an individual `surrender` option; the existing commander side-level surrender option remains available at the same side boundary. The response selects option IDs only; it supplies no rolls, damage, numeric mechanics, free-form actions, or unissued identities. Python rejects missing, duplicate, malformed, unknown-actor, and unknown-option selections and substitutes the existing rule-tier choice with one bounded reason per actor. A selected flee consumes that creature's action, resolves as Disengage (no opportunity attacks), makes no attack that turn, and marks the creature `defeated` with `defeatReason=fled` at the end of its turn; no grid movement is simulated. Individual or side surrender marks the affected living creature(s) `defeated` with `defeatReason=surrendered`. If mechanics or round/lifecycle preflight is unsupported, skip the tactical request and retain the 4b whole-batch fallback. A requested plan that is unusable defaults to rule-tier choices and is never followed by a second plan or validation request; router terminal outcomes retain existing terminal handling.

This keeps tactical choice strictly inside the existing deterministic action allowlist. The complete ledger is still planned before mutation, and unsupported work cannot create a partially resolved prefix.

**Simpler alternative considered:** Let the model emit attack text or numbers and parse them. Rejected because that would create a second mechanics authority and expand the attack allowlist.

### D3. Project only encounter perception and legal options

The tactical request is assembled from the current enemy batch, its eligible actors, bounded current combat facts needed to select options, and the menu itself. Target identities come only from the existing resolver's legal target set; cover identities come only from explicitly authored and eligible features. An eligible actor may also receive its own bounded disposition text from that actor's monster-definition `description`; normalize whitespace, retain printable characters only, and cap it at 240 characters. Missing or malformed descriptions are omitted, and no description for absent actors is projected. Do not include module-wide rosters, world atlas, hidden facts, arbitrary coordinates, absent actors, or prose-derived targets. Omission is not converted into a claim that a fact is false. Validate the returned selection against the same immutable menu snapshot used to build the request.

**Simpler alternative considered:** Reuse the full narrator context. Rejected because it exposes unrelated and potentially hidden information while adding no legal choices.

### D4. Offer per-creature self-preservation without adding statuses

When a supported batch has one living designated commander, replace the 4b near-death decline for that commander-led side with legal self-preservation choices. A living creature at or below the existing bloodied boundary (positive HP <=50% max HP) may flee individually; a commander may also issue a Python-menu withdrawal order, which makes a conditional per-creature flee option legal for each living squad member. A flee consumes that creature's action as Disengage, grants no opportunity attacks, makes no attack that turn, and resolves at the end of its turn without grid/position movement. Persist the result as `status=defeated` and `defeatReason=fled`. Individual surrender is offered at the existing positive-HP <=25% near-death boundary; the commander side-level surrender option remains available when any scheduled enemy reaches that boundary. Surrender marks the individual or all living side members `status=defeated` and `defeatReason=surrendered`. The commander itself can flee or surrender.

`defeatReason` is an optional encounter-creature field with values `fled` and `surrendered`; absence means a legacy defeat and does not change legacy state interpretation. On a flee, remove that creature from subsequent actor and target menus immediately after its turn. G5T derives removal from a later `combat_tactical_plan_result` when one exists; if a later batch has no plan result because the existing whole-batch fallback ran, it may use exactly one accepted fallback batch's eligible cohort and bounded actor/affected-entity records together with the persisted defeated entry. Missing or ambiguous fallback evidence remains blocked. If the commander flees, the current batch's already-validated choices remain bounded by its issued menu; the side has no living commander for the next batch, so the existing rule-tier selection and 4b leader-down whole-batch decline/fallback apply. Rule-tier sides keep the 4b near-death decline unchanged.

Fleeing or surrendering uses the existing `defeated`-enemy combat-exit and XP paths unchanged. 5e XP for overcoming an enemy includes creatures driven off; this change reuses the current XP implementation as-is and does not alter XP policy. Narration receives each resolved `defeatReason` so it can describe flight or surrender accurately without asserting mechanics not present in the ledger.

This replaces the 4b near-death decline only for a supported commander-led batch, permits individual self-preservation without inventing a new status, and does not weaken leader-down or unsupported-batch guards.

**Simpler alternative considered:** Keep side-level surrender as the only self-preservation choice. Rejected because it cannot let an individual intelligent creature save itself while its allies continue. Adding a `fled` status or position movement is also rejected: the existing lifecycle already handles `defeated`, and no grid movement is modeled.

### D5. Resolve cover through encounter state and one effective-AC contract

Add location-authored `tacticalFeatures` with `featureId`, `name`, `kind=cover`, `coverType` (`half` or `three_quarters`), and non-empty `usableBy`. Only explicit schema-valid features become options; no cover is inferred from prose, `tactical_grid`, or positions. Taking cover is movement and does not consume an attack slot: a plan may select one cover option alone or append one cover option after all of an actor's attack-slot choices when every selected attack is ranged. A cover-plus-melee selection is invalid and defaults that actor's plan choice, because an applied melee attack clears cover in the final projection. Hold, flee, and surrender remain whole-turn choices and cannot be combined with attacks or cover. A selected feature updates the affected encounter combatant's `coverFeatureId` and `coverType` in the final encounter projection. Across batches, cover persists only when the combatant's subsequent applied choice is hold, a ranged weapon attack, or selecting the same cover again; selecting a different legal cover replaces the prior reference. An applied melee weapon attack, flee, surrender, defeat, or death clears both cover fields in that batch's single final encounter projection. Cover is not written to character files. Effective-AC lookups apply cover only when the referenced creature belongs to the currently active encounter in an in-progress combat. After exit, fields may remain on the completed encounter but are inert and are not cleared by a separate exit write. A new or restarted encounter starts cover-free; the seeding/start path must not carry cover forward, and stale cover is cleared only in an existing start-of-encounter write if one exists.

Classify an attack from authored action data only: use explicit range/attack-type metadata where present, or an unambiguous authored weapon name. Each projected attack option also exposes a bounded `cover_compatible` boolean, true only for an action Python classifies as ranged. The commander prompt may pair cover with attack slots only when every selected attack option is marked compatible; Python retains the final legality check, and a melee or unknown attack still rejects cover-plus-attack for that actor. The initial survey of the existing `modules/*/monsters/*.json` action records found 1,200 actions across 665 files, with only `name`, `attackBonus`, `damageDice`, `damageBonus`, and `damageType`; this describes the surveyed module corpus, not a ban on adding explicit metadata to isolated fixtures. The G5T Goblin fixture therefore authors its SRD Shortbow as ranged (`attackType=ranged`, normal range 80 ft., long range 320 ft.) and declares one Shortbow attack in its multiattack, keeping the covered-target scenario a legal ranged attack. The G5T Hobgoblin Captain fixture declares a legal two-Javelin multiattack and authors thrown Javelin as ranged (`attackType=ranged`, normal range 30 ft., long range 120 ft.); its Longsword is explicitly melee. When authored data cannot unambiguously distinguish ranged from melee, treat the attack as melee and clear cover. Do not infer range from prose or damage type. The shared effective-AC lookup adds +2 for half cover or +5 for three-quarters cover, rejects stale/malformed references without a bonus, and never stacks cover. Wire both the deterministic enemy target-AC lookup and PC `/att` target-AC lookup through this contract; record the effective AC used in the ledger. The G5T behavior fixture applies cover to an enemy so a later PC attack proves the PC `/att` seam; provider-free tests seed a covered PC encounter entry to prove the resolver seam. This change does not add a new player cover-acquisition action.

Cover selection and in-combat expiration are folded into the final encounter write already owned by the batch and add no write of their own. Encounter exit does not add a cleanup write: the active-combat guard makes completed-encounter cover inert. New/restarted encounter initialization must not copy cover fields from a completed encounter and may clear them only as part of an existing start-of-encounter write, never by adding a write. The G5T per-batch write target is defined in D9.

**Simpler alternative considered:** Add cover bonuses only to narration or attack-specific code. Rejected because those choices can disagree between PC and enemy attacks and cannot be audited from authoritative state.

### D6. Prefetch conditional standing orders and compile them against current menus

`COMBAT_TACTICAL_PREFETCH_ENABLED` defaults false and requires both the tactical-brain and deterministic-resolver flags. When all three flags are enabled and an upcoming commander batch is identified, submit one background standing-orders request when the PC phase starts: after initiative at combat start, and after each enemy batch completes. Bind each process-local receipt to the bounded encounter ID, round-batch ID, and enemy roster identity. Do not use a full menu/perception snapshot fingerprint as a freshness gate. The PC phase is never considered complete by counting PC actions: the human DM owns `/end`, and PCs may make any number of attacks in a round.

Standing orders are strict, bounded conditional rules in Python vocabulary, not concrete option IDs. For each living scheduled enemy actor, allow an ordered list of zero to four `{when, do}` clauses. `when` is a closed enum: `always`, `self_bloodied`, `self_near_death`, `commander_down`, `cover_available`, and `ally_departed`; Python evaluates these against authoritative state. `do` is a closed menu-kind union: `attack` with target identity and optional action name, `take_cover` with optional feature ID, `flee`, `surrender`, or `hold`. The commander may also provide at most one conditional withdrawal-order clause and one conditional side-surrender clause. Bound the actor and clause counts, use a strict schema with no extra properties, and permit only an optional short intent string capped at 160 characters for narration/trace; intent text never affects mechanics.

Python MAY submit one re-plan for the same batch after a major PC-phase state change: commander defeated or departed; an enemy newly bloodied or near-death; a targeted PC dropping to 0 HP or leaving; or an enemy roster change. The total is at most two background standing-order requests per batch (initial plus one re-plan), never a trigger based on PC action counts. A newer completed, schema-valid order set supersedes the prior set; the prior completed set remains usable until replacement completes. Each request retains its own roster-identity provenance while remaining bound to the same encounter and round batch.

At `/end`, Python builds the current legal menus exactly as synchronous planning does, then scans each actor's clauses in order. The first clause whose condition holds and whose kind/target maps to current legal menu option ID(s) wins; if its requested option is not currently legal, scanning continues. Side clauses apply only when the corresponding commander menu option is legal now. Python compiles the matched IDs into the existing candidate-plan shape and runs the same plan validator and resolver; the decision source remains `llm_tactical` and the trace carries a bounded `plan_origin=standing_orders` marker. No model planning call occurs at `/end`. If no clause maps for an actor, use the rule-tier default with a bounded `default_reason`. Illegal, unknown, or unmappable orders never reach mechanics.

Once the standing-orders path is selected for an eligible batch, do not wait at `/end` and do not make a synchronous plan request if no completed, schema-valid order set is available (including pending, failed, cancelled, expired, or schema-invalid results). All actors use rule-tier defaults and the bounded outcome `standing_orders_unavailable`. If prefetch is disabled or the batch is ineligible and nothing was submitted, preserve the existing single synchronous plan path unchanged.

Receipts are process-local, protected by a lock, and have a bounded deadline. Invalidate them on encounter exit or batch completion; late results are ignored without state writes or attribution to a later batch. Workers receive only immutable request data and never mutate combat state. Failures fail open, while router-owned retry and terminal behavior remains unchanged. Trace and count background standing-order requests under their own site/attribution, capped separately at two per batch; the primary G5T acceptance limit of at most two synchronous requests per accepted batch is unchanged, and prefetch captures remain optional and separate from primary acceptance.

**Simpler alternative considered:** Consume a prefetched concrete plan only when its full menu/perception fingerprint still matches. Rejected because PCs act during the PC phase, so their actions almost always change that snapshot and cause the plan to be discarded. Waiting for a model signal that all PCs have acted was also considered and rejected: the runtime has no such signal, the DM owns `/end`, and per-PC action counts cannot define phase completion because a PC may attack any number of times.

### D7. Add bounded tactical trace fields and a distinct tactical decision source

Preserve existing decision sources and add `llm_tactical` for a commander candidate plan; `llm_fallback` retains its existing meaning. Keep `tactical_plan_outcome` bounded to `accepted`, `partially_defaulted`, and `rejected_all`; add bounded `plan_origin` and `standing_orders_outcome` markers, including `standing_orders` and `standing_orders_unavailable`, plus bounded per-actor default reason codes. Add a per-creature `self_preservation_outcome` enum with `fled` and `surrendered`, corresponding to the persisted `defeatReason`. Trace each background standing-order submission/re-plan, status, distinct site attribution, and outcome with the same run-local `batch_id`, bounded plan/receipt correlation, and run-local actor/feature IDs. Keep the trace observational, opt-in, fail-open, and free of prompts, secrets, absolute paths, and unbounded narrative/game-state data. The report computes only from observed records; it does not infer missing outcomes.

**Simpler alternative considered:** Put tactical state into prompt or encounter snapshots in the trace. Rejected because that leaks sensitive/unbounded payloads and is unnecessary for aggregate decisions.

### D8. Keep tactical flags inert behind the existing resolver gate

The existing `COMBAT_TACTICAL_BRAIN_ENABLED = False` and `COMBAT_TACTICAL_PREFETCH_ENABLED = False` flags remain default-off; the brain requires `DETERMINISTIC_ENEMY_RESOLUTION_ENABLED=true`, and standing-orders prefetch requires all three flags. With the brain flag off, `tactics=commander` is inert and 4b behavior remains unchanged. With the brain on and prefetch off or ineligible, an eligible commander plan is synchronous. The seeder may enable these flags only inside the isolated G5T sandbox; no shipped flag default changes in this change.

**Simpler alternative considered:** Enable commander mode whenever encounter data declares a commander. Rejected because authored data must not bypass the explicit rollout gates.

### D9. Extend G5 capture tooling with isolated G5T scenarios and preserve all prior gate behavior

The G5T Goblin disposition explicitly prefers flight over attacking or taking cover when a bloodied actor is offered direct flee, references Nimble Escape, and reserves individual surrender for being cornered or near death. The bounded flee menu label explains Disengage, no attack, and departure at turn end. These are tactical guidance and menu semantics only: the fixture does not force a flee. Any corrections to the fixed G5T scripts or authored attack data are defined separately in D10. A full-health round-1 actor has no direct flee or surrender option; above-bloodied conditional flee can become legal only if the commander chooses the withdrawal order.

Add new named `g5t-commander-p1` and `g5t-commander-p4` scenarios in Capture_Arena, using a Hobgoblin Captain with explicit commander authority, cowardly goblins with an authored SRD Shortbow multiattack, and authored cover. A bounded actor-scoped disposition description makes the goblins' willingness to flee observable, but neither cover nor flee is forced. Each scenario scripts a bloodied-but-living goblin into an `/end` in both party shapes, an Extra Attack turn with two legal `/att` + `/dmg` pairs by Acheron in one round, a near-death surrender opportunity, an attack against a covered creature, and exit/cover-expiration checks. After the final PC strikes, a distinct final DM `/end` batch step SHALL run the existing enemy-batch AUTO_EXIT/XP flow; if an earlier batch already exits combat, the driver records the closing step as skipped with `combat_ended`. The driver waits for `combat_exit_complete` on a sent closing step before after-run capture. Evidence verifies any fleeing creature is absent from later actor and target menus and the remaining encounter state is coherent. Capture three independent runs for each party shape on one source revision; retain full bundles under `tmp/router-rollout/g5t/<run-id>/` with scenario/seed/source/provider identity, expected-vs-observed assertions, traces, snapshots, and reports. For primary G5T acceptance with prefetch disabled, require at most two synchronous provider requests per accepted commander batch (one plan, one narration, zero validation), at most one history write plus one encounter write plus one character write per distinct character whose canonical state changed in that batch (total `<= 2 + changed_character_count`), 100% applied-choice legality, and <=15000 ms median batch work-only latency per shape across three runs. The automated report is evidence, not the verdict; the primary reviewer records PASS/FAIL/BLOCKED. An optional prefetch sub-gate reports background standing-order requests separately and cannot waive primary targets. G5T's own pre-gate fixture corrections may update its script hash and derived caps; G1/G3/G4/G5/G5R selectors, fixtures, action scripts, identities, hashes, and evaluators remain unchanged. Keep both shipped tactical flags off pending primary-reviewed PASS and separate rollout approval.

**Simpler alternative considered:** Reuse G5R P1/P4 scripts and relabel the runs. Rejected because it would change G5R identity/evaluator semantics and would not provide commander-specific behavioral evidence.

### D10. Freeze branch-robust G5T scripts and derive all capture caps

G5T P1/P4 use separate fixed scripts; existing G1/G3/G4/G5/G5R scripts, identities, and evaluator behavior remain unchanged. Both fixtures start at full enemy HP: Captain 39/39, Squad A 7/7, and Squad B 7/7 (maxima remain authored at 39/7/7). Squad B starts with the authored half-cover feature on its encounter entry. This ensures the round-1 `/end` has no direct flee or surrender option; a conditional flee above bloodied can become legal only if the commander selects the withdrawal order. Acheron's equipped training blade declares `1d6+2 slashing`, and his class features include SRD Extra Attack.

P1 sends: round 1 `/end`; round 2 Acheron's covered Squad B attack at roll 19 + `/dmg 4`, then his Extra Attack strike against Squad A at roll 19 + `/dmg 4`, then `/end`; round 3 Acheron attacks Squad A with roll 19 + `/dmg 3` and Squad B with roll 19 + `/dmg 4`, then `/end`; round 4 Acheron makes two Extra Attack strikes against the Captain, each roll 19 for `/dmg 8`, then `/end`; round 5 Acheron attacks Squad B with roll 19 + `/dmg 3` and the Captain with roll 19 + `/dmg 3`, then `/end`; round 6 Acheron attacks the Captain with roll 19 + `/dmg 6` and roll 19 + `/dmg 5`, then `/end`; round 7 Acheron makes two final Extra Attack strikes against the Captain, roll 19 + `/dmg 3` and roll 19 + `/dmg 6`, defeating the last survivor, followed by the distinct final enemy-phase `/end` closing batch that runs existing combat exit and XP handling.

P4 sends: round 1 `/end`; round 2 Acheron's covered Squad B attack at roll 19 + `/dmg 4`, his Extra Attack miss against Squad B at roll 1 with paired `/dmg 3`, then Merisiel, Kira, and Vitreol each attack the Captain at roll 19 + `/dmg 3`, followed by `/end`; round 3 Acheron makes two Extra Attack strikes, against Squad A with roll 19 + `/dmg 4` and Squad B with roll 19 + `/dmg 4`, then Merisiel, Kira, and Vitreol each attack the Captain at roll 19 + `/dmg 3`, followed by `/end`; round 4 Acheron attacks Squad B with roll 19 + `/dmg 3` and the Captain with roll 19 + `/dmg 3`, then Merisiel, Kira, and Vitreol each attack the Captain at roll 19 + `/dmg 3`, followed by `/end`; round 5 Merisiel attacks Squad A with roll 19 + `/dmg 3`, then `/end` gives the living near-death Captain a second surrender opportunity after the goblins have fled or been defeated; round 6 Acheron makes two final Extra Attack strikes against the Captain, each at roll 19 + `/dmg 5`, defeating the last survivor, followed by the distinct final enemy-phase `/end` closing batch that runs existing combat exit and XP handling. Every other hit roll is 19, so no scripted hit is a natural-20 critical; all damage values are within the acting PC's weapon range.

The covered attack's hit and miss branches are both simulated: P1 has Squad A at 3/7 at round-2 `/end` in either branch; P4 has Squad A at 3/7 at round-3 `/end` in either branch. These are bloodied but not near-death, so individual flee is legal without making surrender legal. P1's Captain first reaches 9/39 at round-6 `/end`; P4 first reaches 9/39 at round-4 `/end` and remains at 9/39 at the round-5 `/end`, after the remaining goblin is defeated or has fled. The second P4 surrender opportunity is legal in both covered-attack branches. At these opportunities the Captain is alive; when enemies keep fighting, the remaining fixed PC steps defeat every survivor before the distinct final closing batch.

The scripts contain 31 P1 steps/7 enemy batches and 42 P4 steps/6 batches, including the distinct final `/end` exit-closing batch in each shape. With the initial active-PC selection plus script-derived switches (P1: 1; P4: 14), `max_requests=max_controls=steps+1+switches`: P1 33, P4 57; `max_inputs=max_steps` is 31/42. The closing batch is sent even when PC attacks have defeated all enemies; only a prior observed combat exit makes it a skipped `combat_ended` receipt. A sent closing step requires the matching post-combat `combat_exit_complete` trace marker before after-run capture. Maximum damage per combat batch is 16 from the Captain's two Javelins plus 8 from each Goblin, or 32; the closing batch has no live enemies and adds no attack damage. Therefore the damage bound covers six P1 and five P4 combat batches: P1 worst-case PC damage is 192 and seeded PC HP is 193; P4 is 160 and HP is 161. One shared helper derives these bounds from the authored multiattack definitions.

### D11. Keep covered-attack branching local and preserve skipped-step evidence

The covered-target script row is an attack only for purposes of outcome evidence; its paired `/dmg` row is sent only when the driver's parsed attack output confirms a hit. The G5T driver may skip a damage row after a miss, an attack row whose target is authoritatively inactive, or remaining rows after canonical combat exit. The final `/end` closing row has no target and SHALL still be sent after all PC targets are inactive while combat remains active. If an earlier batch exits combat, that closing row is skipped with `skip_reason=combat_ended` and no command is sent to the ended session. A sent closing batch waits for `combat_exit_complete` rather than accepting only an ordinary `turn_end` marker. Each skipped row still receives a bounded `status=skipped` receipt with its script-step identity and reason but no timing window. Sent receipts retain script-step identity independently of socket-attempt indexing. The report excludes only explicitly `combat_ended` skipped batch rows from batch-timing requirements; other missing or ambiguous batch evidence remains blocking. Per-run absence of conditional self-preservation/cover behavior is `NOT_OBSERVED`; only cross-run missing coverage blocks shape acceptance.

**Simpler alternative considered:** Infer a hit or combat exit from transcript wording and remove skipped rows from the fixture. Rejected because branch execution must use canonical sandbox state and retain a complete, auditable receipt for every authored script row.

### D12. Make surrender a clear but non-forced choice for an abandoned commander

The G5T Hobgoblin Captain fixture authors a bounded disposition stating that he prefers to yield rather than die pointlessly when near death after his troops have fled or fallen. The commander-plan prompt treats a near-death commander who is the only eligible enemy actor as abandoned and strongly prefers one of the issued individual or side-level surrender options; it explicitly does not force that choice. Menu eligibility, option validation, and Python-owned outcomes remain unchanged. This closes the guidance gap without changing combat mechanics or bypassing the commander.

**Simpler alternative considered:** Change surrender eligibility, auto-select surrender in Python, or alter the fixed script/damage. Rejected because the existing menu already issues legal surrender options, and the encounter must continue to allow a validated commander choice.

## Risks / Trade-offs

- **Invalid or partial model plan:** The validator applies only issued option IDs; per-actor failures default to Python's rule tier. No raw plan value reaches mechanics.
- **Standing orders may be absent or unmappable:** Current-menu compilation rejects vanished or illegal targets and uses rule-tier defaults when no clause applies; an unavailable selected prefetch path never adds a synchronous planner call, and the bounded outcome is reported separately.
- **Cover schema/data drift:** Unknown feature IDs, unsupported types, or mismatched encounter references grant no bonus and are traceable as bounded outcomes.
- **Existing 4b behavior changes at near death:** Only an authorized living commander makes a near-death batch eligible for tactical choices; rule-tier sides, absent/down/ambiguous commanders, and all other declines keep the existing fallback.
- **Flight or surrender can be misreported:** Persist only existing `defeated` status plus optional `defeatReason`, remove actors from subsequent menus, and pass the reason to narration; reuse existing exit/XP handling without an XP-policy change.
- **Write budget:** Cover must be included in the encounter projection's existing write; an extra write beyond the history/encounter plus changed-character allowance is an absolute G5T failure and blocks acceptance.
- **Capture compatibility:** G5T uses new names and a new evidence root; unchanged selectors and golden fixture identity checks are re-run before live capture.

## Migration Plan

1. Add optional encounter/location schema fields and author only the isolated Capture_Arena fixtures. Existing encounters and locations without these fields remain valid and use rule behavior.
2. Build provider-free menu construction, perception projection, option validation, and fallback tests before wiring a provider call.
3. Integrate one synchronous commander plan after whole-batch eligibility and before the existing resolver ledger is finalized. Add legal per-creature flee/surrender and commander side surrender through the existing `defeated`/exit/XP lifecycle; preserve rule-tier near-death and all other 4b fallback boundaries.
4. Add encounter cover and shared effective-AC lookup to enemy resolution and PC `/att`; keep cover in the final encounter projection.
5. Extend trace, report, and capture selectors. Verify existing gate outputs/identities remain unchanged before any G5T live run.
6. Reuse the existing default-off flags and add PC-phase-start standing-order submission, current-menu `/end` compilation, one bounded event-triggered re-plan, receipt invalidation/late-result handling, separate background accounting, and provider-free lifecycle tests.
7. After focused and baseline suites pass and the primary orchestrator authorizes it, run three P1 and three P4 G5T captures, review behavioral evidence and absolute targets, and record the verdict. Run optional prefetch captures separately.
8. Keep shipped flags false. G5T PASS supports, but does not itself authorize, a distinct rollout decision.
