## Current API and compatibility evidence

- Main `get_ai_response()` uses `utils.provider_response_recovery.request_chat_completion_with_recovery`; that helper currently retries only empty transient responses, returns refusal/filter responses unchanged, and applies `EMPTY_RESPONSE_RETRY_LIMIT = 2` per helper invocation. The facade migration preserves up to 3 empty responses on preferred and up to 3 on the sole fallback, with a shared one-fallback flag and six-call cap; every response/transport attempt is observed exactly once.
- Combat dependency seams are the named extracted stages in `core/combat/bootstrap.py`, `turn.py`, and `validation.py`; tests already fake their client/parameter/trace/tracker dependencies. Legacy direct-chat source-contract assertions in `scripts/test_gpt54_chat_params_contract.py`, `scripts/test_gpt54_mini_chat_params_shim.py`, `scripts/test_combat_validation_stage.py`, and `scripts/test_combat_retry_stage.py` must be repointed to the fake `llm.call`/transport seam without reducing asserted prompt, output, retry, trace, and usage behavior.
- Existing baseline references: 705 combat/decomposition tests were reported across 41 isolated processes in `openspec/changes/combat-manager-decomposition/reports/task-5-4-final-verification.md`; the facade baseline is 131 tests per `openspec/changes/llm-router-facade/reports/final-verification.md`. These are references, not a request to relabel prior outcomes or weaken current contracts.
- The 15 semantic operations above are the full current scope. All 15 are migrated, including starting-location analysis, transition narration, and NPC movement; the current 15/15 inventory has zero legacy transport variants. Keep unlisted direct chat call sites out unless a fresh source check proves they are a transport variant of one listed operation.
- Session reset source boundary: CLI launch enters `main.main()` at `main.py:8730`; it hydrates files at 8814-8817 and enters `main_game_loop()` at 8876. Web launch enters `web.web_interface.run_game_loop()` at 4503, hydrates at 4507-4512, then calls `dm_main.main_game_loop()` at 4519. `main_game_loop()` is also recursively called after save restore (`core/ai/action_handler.py:3419` returns restart; `main.py:8402-8404` re-enters the loop), so reset only in the two runtime launch hooks before the first core call, never in the loop. A runtime launch is not a new campaign. Reset router-local stats and existing fallback notification state only; do not reset legacy rolling-week usage.
